# Elexon snapshot

`snapshot.json` is a real offline snapshot of Elexon Insights Solution data, fetched by `python -m backend.refresh`. It is not generated demo data. Raw daily responses are cached under `work/source-cache` (ignored by Git). The committed snapshot retains all hourly forecast versions relevant to the Jan 2–Feb 1 UK delivery days and every actual version returned. Source URL, returned record count, and retrieval time are recorded for each of 63 daily requests. The snapshot identifier is a SHA256 hash of the normalized forecast and actual arrays. Per-source retrieval times can differ after a cached refresh; top-level retrieval time is their latest. Refresh is explicit and requires network access; no API request calls Elexon.

WINDFOR requests cover publication dates Dec 31 2025–Jan 31 2026, inclusive. Each daily publication range ends at the next midnight (inclusive) so fractional-second publications at the end of the day are retained; repeated midnight rows collapse deterministically. Forecast publications from Feb 1 onward are excluded from the pilot. The prior day provides eligible records even at a Jan 1 00:00 cutoff. FUELHH WIND requests cover settlement dates Jan 2–Feb 1 2026. API stream endpoints return arrays, with no pagination parameters in the Elexon OpenAPI schema. Requests use four workers, 45-second timeouts and up to three attempts with bounded backoff. Each date's successful array is cached separately, and the previous snapshot is replaced atomically only after a successful complete refresh and validation. Cache entries are invalidated when the source URL changes.

## Alignment and eligibility

Observed WINDFOR records are hourly. The pilot explicitly holds each hourly MW value constant for its two half-hours. It does not interpolate between hours or fill missing source hours. Both halves retain the original publication time and `sourceStartTime` lineage. Thus half-hour error includes actual variability within the source hour. This alignment assumption is present in the API warnings and CSV. FUELHH actuals have half-hour settlement timestamps. All source timestamps must have explicit offsets and are normalized to UTC, preserving fractional publication seconds for cutoff comparisons; UK decision/delivery calendar boundaries use `Europe/London`. January is GMT; the calendar helper also handles 46/50 interval DST days.

`/api/health` deliberately returns HTTP 200 for diagnostic reachability, with `status: degraded, dataLoaded: false` when the snapshot cannot load. Readiness checks must inspect `dataLoaded`. Analysis and export return HTTP 503 for absent, malformed, or hash-mismatched snapshots. The validated snapshot is cached in process; restart after a refresh to switch snapshots.

For every delivery half-hour independently, select the greatest `publishTime <= decision cutoff`. A null in the latest eligible source row stays null and does not fall back to an older usable value. Actuals use the latest returned publication for that interval and are hindsight only. Actuals never choose forecasts. Identical same-target/same-publication duplicates collapse. Conflicting duplicate values become null with an audit warning; no arbitrary winner is selected. Invalid source rows are rejected with a count. Non-finite, negative, boolean, misaligned, naive-timestamp or inconsistent actual settlement-period rows are invalid. Zero is a valid value. Data outside the delivery window is deliberately filtered.

This is a civil-day January 2026 pilot: decision dates Jan 1–31 buy Jan 2–Feb 1. The default 09:00 local cutoff is a pre-auction planning assumption, not a claim about exchange timetables. Elexon publication time approximates availability; ingestion latency is unknown. No attempt is made to reconstruct later actual revisions as they were known in January. WINDFOR and FUELHH can differ in measured/forecast wind coverage; neither is asserted to represent all UK wind, and the difference is not solely forecast skill.

## Retrospective metrics

Error is forecast minus actual MW; positive means wind shortfall against expectation. MAE, signed bias, RMSE, linearly interpolated P90 absolute error, and maximum positive overforecast use paired non-null intervals only. Maximum overforecast is zero if all paired errors are non-positive. Counts and expected denominators accompany every summary. P90 is observed historical error, not a prospective confidence guarantee. Zero denominators yield null metrics; no MAPE is calculated. Forecast and actual energy independently equal `sum(MW * 0.5)` MWh only with complete coverage of their entire expected period; otherwise each energy value is null. CSV nulls are empty cells, never zeros.
